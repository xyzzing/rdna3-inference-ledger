# Campaign update — Nov 11/12, 2026: the correctness arc, the session-lookup arc, and the measurement discipline that settled them

One long night, three authorized GPU windows, ~15 more recorded experiments on top of the
~110 — and two complete story arcs closed with the strongest single instrument of the whole
campaign. Same hardware (RX 7900 XTX / gfx1100), same model (Qwen3.8 Flash-Next MoE, IQ3_S),
same protocol: predeclared gates, paired measurement, never relax a bar after the fact.

**Headline: the session-lookup idea — "let the drafter reuse text the session already
produced" — was chased all the way from a paper claim to a drift-matched live measurement,
and it lost.** Along the way it produced the campaign's tightest measurement floor to date
(±0.5%), a new instrument (the trailing-twin drift probe), and five engineering lessons now
written into [lessons/](lessons/).

## Arc 1 — ONECOMMIT: from "wrong answers" to "0.49%, and it isn't the flag"

ONECOMMIT is a proposed engine switch: when a speculative window commits exactly one token,
skip the separate commit-graph launch (the theory: one launch saved per such window).

| step | result |
|---|---|
| First report (0050, instrumented) | the flag **changed the output text** — treated as a correctness blocker |
| Controlled re-run at depth-1 windows (0056) | **no divergence anywhere** — but only at uniform 1-token windows |
| Controlled re-run at production config, instruments off (0057) | off/on **differed on two fixtures** — looked like a reproduction |
| Controlled re-run with a proper off/off noise floor + a per-window state tap (0058) | **completely clean through 116 windows including 47 engaged self-commits** — the 0057 "reproduction" was over-attribution: its pairs had no noise floor |
| The price (independent of all correctness) | 43 eligible windows × ~0.3 ms of saved launch ≈ **15 ms** against a 3,102 ms decode wall = **0.49%**; the 2% promotion bar needs **60.8 ms** |

**Verdicts:** the divergence class = *intermittent fresh-instance numerics flipping the
drafter's min-p knife edges* (the width decision sits on a rounding boundary; a 1-ULP
probability change flips whole rows — observed once as a 3-vs-8 token window flip, never
again under control). The flag is **not implicated by any controlled measurement**. And the
performance question is closed by arithmetic alone: **even a perfect fix could not clear the
bar, so no timing window was ever spent on it.** Lesson: separate "is it correct?" from "is
it worth it?" — here the second question was answerable with a stopwatch and a multiplication.

## Arc 2 — session lookup: the idea that survived three filters and died on the fourth

The idea: extend the drafter's lookup table with the session's earlier turns, so repetitive
work (code edits, tool output) drafts itself. The arc, each stage with a predeclared gate:

1. **Offline supply (priced, held out):** on chronological coding sessions the session
   source proposes correct continuations for +591k positions beyond the request-local table;
   net estimate +9.3% on held-out turns. **A capped "recent spans" table measured NEGATIVE**
   (−2.3 to −3%: its longer matches are often wrong — displacement dominates).
2. **Live Q&A screen:** engaged, **0 conversions** — the fixture's outputs don't repeat
   session spans. Honest close: the supply exists only where outputs literally reuse history.
3. **The edit-session class (this update):** generated sessions where each turn re-edits the
   previous turn's output (the class the offline supply predicted). The bypass **engaged on
   every turn** and session drafts **converted at 24%** — 17 of 71 drafts accepted in the
   first window, far above the 0/5 and 2/13 of earlier fixtures. The reopening condition was
   satisfied exactly as written.
4. **Token-matched measurement — the fourth filter, and the one that held.** With the
   candidate forced to replay the baseline's exact committed token stream (the follow pipe),
   three vehicles were run in one engine process:
   - the naive comparison (candidate last): **won every block, +13–15%, CI above zero** —
   - the drift-matched comparison (a trailing twin replays the baseline's ids in the LAST
     slot, measuring position drift directly): the position-drift floor measured **±0.5%**
     (the earlier 31% "floor" was the slot-1 freshness artifact — the first request after an
     instance start runs ~12% faster than every later slot), and the candidate measured
     **+10 to +13% SLOWER than stock on identical committed tokens**, losing 14/15 (dev) and
     10/10 (held-out) blocks.

**Verdict: SCOPED NEGATIVE — lookup-replaces-MTP is closed in all implemented forms** (the
post-draft window reshape measured −4 to −8.5%; the pre-draft skip measured +10–13% slower
drift-matched). Accepted session drafts are real; they are just not worth their window cost
against a neural drafter running at 94% top-1 acceptance. The full chain — supply, conversion,
cost — was needed to close it honestly; any single stage would have produced a wrong answer
(the supply alone predicts +9%; the naive comparison "measures" +13%).

## Also closed this update

- **Q6_K scheduling candidates** (scale hoisting, unpack reuse across verification rows):
  bitwise-correct, family speedup **1.015–1.017× vs the 1.30× screen** — the duplicated
  decode work costs ~0; it hides under the weight-traffic memory time. Closed.
- **Shared/routed expert overlap** and **verification readback**: both already done by the
  engine (expert branches already stream-separated; sampling already device-side, ids-only) —
  closed from saved traces without new GPU time.
- **Verification-width invariance**: a five-arm operator harness (window vs serial, forced
  prefixes, zero-acceptance, a stale-tail probe, A–A twice) — bitwise exact, including the
  commit-graph route at width. Kept as a regression test.
- **The GDN "output-gate vs recurrence" overlap idea**: closed by inspection — the recurrence
  consumes the gate projection's output; intrinsic data dependence, ceiling ≈23 ms < 60.8 ms.
- **A compiler-grade build-isolation gate** now fronts every build (canonical-path guard +
  an unprivileged read-only namespace): after one incident where a rebuild briefly overwrote
  the production binary's path, the guard rejects — validated against decoys and symlink
  aliases — anything that could touch production, and the isolated build runs in a namespace
  where production is mounted read-only.

## The new measurement lesson (instrument-grade)

**The slot-1 freshness artifact:** the first request after an instance start runs ~12% faster
than every later slot. Any comparison whose baseline sits in slot 1 is systematically wrong —
it measured a "+13–15%" win that the drift-matched rerun reversed to "−10 to −13%". The fix
is structural: a **trailing twin** (a stock re-run of the identical token stream in the LAST
slot) measures position drift directly; the candidate is then judged against its own slot,
not against the anomaly. The drift floor measured ±0.5% — tight enough to resolve 2%.

Also recorded: cross-instance A–A floors measured 12–60% per block on this fixture class —
never compare across instances at the 2% scale.
